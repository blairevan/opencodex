# 可用账户数量与状态提示设计

## 目标

将账号区域标题从“可用账户”改为“可用账户[x/y]”，其中 x 表示当前正常可用账号数量，y 表示已登录账号总数。标题悬停时展示各状态数量，数量为 0 的状态不显示。

## 计数规则

- `y`：账号列表总数，包含停用、被限制、需要重新登录和额度不可用账号。
- `x`：状态为“正常”的账号数量。
- 状态采用互斥优先级，避免同一账号重复计数：
  1. 手动停用：`enabled === false`。
  2. 需要重新登录：`needsReauth === true` 或健康状态为 `reauth_required`。
  3. 被限制：健康状态为 `cooldown`。
  4. 额度不可用：`quotaUnavailable === true` 或其他已知异常状态。
  5. 正常：不属于以上状态的已启用账号。
- 正常账号数量 x 只统计最后一类。

## Hover 展示

使用标题的原生 `title` 和可访问描述展示状态明细，例如：

```text
正常：2
被限制：1
手动停用：1
需要重新登录：1
```

状态按固定顺序输出，数量为 0 的状态不输出。标题本身继续通过 i18n 渲染，Hover 文案使用多行结构化文案。

## 数据流与范围

- 复用 `ProviderAuthPanel` 已有的 `accounts`、健康状态和额度不可用字段，不新增后端接口。
- 账号列表和 Codex 专用账号池沿用各自现有标题逻辑；本次重点覆盖 OAuth 账号列表。
- 计数逻辑抽成纯函数，便于单元测试和避免 JSX 内的复杂条件。
- 不保存账号凭据，不改变账号路由、启用/停用、切换和额度查询行为。

## 测试与验收

- 覆盖空列表、全部正常、混合状态和状态优先级冲突。
- 验证数量为 0 的 Hover 行被省略。
- 验证 `x/y` 与状态明细一致。
- GUI 构建、locale parity 和差异检查通过。
- 手工验收标题、Hover 文案及窄屏显示不破坏现有账号操作。
